Evaluating Matrix Elements

The bulk of the work of this package is evaluating the matrix elements of the Hamiltonian. This page focuses on the details of how the matrix elements will be evaluated.

Considerations

  1. Hamiltonian is a sum of terms.

    • The design calls for one class per Hamiltonian term.

    • The matrix elements for the individual terms will be evaluated term by term, and then summed to get the total Hamiltonian matrix element.

  2. Basis functions are assumed to be products of harmonic oscillator wavefunctions and angular momentum eigenstates.

  3. The Hamiltonian will be sparse in the basis set.

    • Whether it’s sparse enough to use sparse matrix libraries is TBD.

    • Initial implementation will focus on filling in the non-zero elements of a dense matrix.

    • Need a mechanism to get non-zero indices.

  4. The anharmonic potential, vibrational coriolis, and rovibrational coupling terms are all products of vibrational operators. We need a mechanism to evaluate matrix elements of products of vibrational operators.

    • The final matrix elements are direct products of per-mode matrix elements; however, the per-mode matrices are extremely sparse.

Helper Functions

  1. non_zero_indices(BraBasis, t, KetBasis). Takes the basis set for the bra, a term in the Hamiltonian, and the basis set for the ket. Returns a generator that runs over bra-ket basis function pairs. The generator only returns pairs that are in general non-zero.

    • The idea to take a bra and a ket is to allow for the using different basis sets or batches of basis functions.

    • One common API. Internally can branch based on the input types.

  2. matrix_element(Bra, t, Ket). Takes a basis function from the bra, a term from the Hamiltonian, and a basis function from the ket. Returns the value of the corresponding matrix element.

    • Similar to non_zero_indices, the idea is to have a common API that can branch internally based on the input types.

    • Could be extended to take a batch of basis functions eventually.

Full Basis: Algorithm 1

This algorithm assumes we are building the full Hamiltonian matrix in a dense format.

  1. Input is the Hamiltonian H and the basis set B.

  2. Loop over Hamiltonian terms, t.

  3. Call non_zero_indices(B,t,B) to get a generator G.

  4. Loop over (b,k) pairs in G.

  5. Call matrix_element(b, t, k) to compute the matrix element.

Vibrational Basis: Algorithm 1

We need to be able to on-the-fly build elements like \(c\braket{\vvec'\mid \op{O}^n \mid\vvec}\), where \(\op{O}^n\) is a product of \(n\) vibrational operators and \(c\) is a coefficient whose value depends on the modes \(\op{O}^n\) operates on. The input to our function will be bra_space, the list of allowed bra states, ket_space, the list of allowed ket states, o, the list of operators, and reducer a function that combines the coefficients. This is implemented by rovib.matrix_elements.vibrational_matrix_elements.vibrational_matrix().

Elements in o are assumed to be PotentialOperator, CoriolisOperator, or WatsonOperator objects.

The first three steps do not depend on the ket, so they are done once.

  1. Let op_range[i] = o[i].vibrational_operators(). Loop over the Cartesian product of op_range. Let op_list be the current list of operators.

  2. Let c[i] = o[i].coefficient(op_list[i]). Call reducer(c) to get the coefficient for this term. If it is zero, skip to the next op_list.

  3. Operators on different modes commute, so group op_list by mode, keeping the order of the operators within each mode. Let word[i] be the operators acting on mode i. Modes with no operators are left out.

The remaining steps are done for each ket.

  1. Loop over the states in ket_space. Let ket be the current ket state and values be an empty map from bra states to matrix elements.

  2. For each term from steps 1-3, and each mode i in word, apply word[i] to the ket’s state of mode i. This gives the allowed values of \(v'_i\) for \(\braket{v'_i\mid \op{O}^{(i)}\mid v_i}\), where \(\op{O}^{(i)}\) is the product in word[i]. For example, if word[i] has 3 operators then the allowed values of \(v'_i\) are such that \(v'_i - v_i\) is one of -3, -1, 1, or 3, and states with \(v'_i < 0\) never appear.

  3. Shifts in each mode are independent, so loop over the Cartesian product of the results of the previous step. Let ket_dp be ket with each mode in word replaced by the current \(v'_i\). If ket_dp is not in bra_space, skip to the next shift.

  4. Add c times the product of the per-mode matrix elements to values[ket_dp]. Different terms can couple the same bra and ket, so the contributions must be summed rather than assigned.

  5. Once all terms are done, set H[bra, ket] = values[bra] for each bra in values.
